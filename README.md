## 📌 Overview

This project implements an **8-bit SPI (Serial Peripheral Interface) Master Controller using Verilog HDL**.

The design supports **SPI Mode 0 (CPOL = 0, CPHA = 0)**, MSB-first serial data transmission, full-duplex communication, configurable clock division, chip-select generation, and transaction status monitoring.

The design is verified using a **Verilog testbench with loopback functionality**, where the transmitted MOSI signal is directly connected to MISO to verify correct data transmission and reception.

# 📖 What is SPI?

**SPI (Serial Peripheral Interface)** is a synchronous, full-duplex serial communication protocol commonly used for communication between a controller and peripheral devices.

Typical SPI peripherals include:

* Sensors
* ADCs
* DACs
* Flash memory
* Displays
* EEPROMs
* Real-time clocks
* Other integrated circuits

SPI communication typically uses four signals:

```text
SCLK
MOSI
MISO
CS
```

---

# 🔌 SPI Signals

| Signal | Full Name           | Direction      | Description                       |
| ------ | ------------------- | -------------- | --------------------------------- |
| `SCLK` | Serial Clock        | Master → Slave | Clock generated by the SPI Master |
| `MOSI` | Master Out Slave In | Master → Slave | Serial data transmitted by Master |
| `MISO` | Master In Slave Out | Slave → Master | Serial data transmitted by Slave  |
| `CS`   | Chip Select         | Master → Slave | Selects the SPI Slave             |

The SPI Master controls the communication by generating the clock and controlling the chip-select signal.

# ⚙️ SPI Mode

This implementation uses:

```text
SPI Mode = 0

CPOL = 0
CPHA = 0
```

### CPOL

Clock polarity determines the idle state of the SPI clock.

```text
CPOL = 0

SCLK idle = LOW
```

### CPHA

Clock phase determines which clock edge is used for sampling and changing data.

For this implementation:

```text
Rising Edge  → Sample MISO
Falling Edge → Change MOSI
```

# 🔄 Data Transfer

The controller transmits data **MSB first**.

For example:

```text
TX Data = 10100101
```

The bits are transmitted in this order:

```text
Bit 7 → Bit 6 → Bit 5 → Bit 4 → Bit 3 → Bit 2 → Bit 1 → Bit 0

  1  →   0   →   1   →   0   →   0   →   1   →   0   →   1
```

During every SPI clock cycle, one bit is transmitted and one bit can be received.

Therefore SPI supports:

```text
Full-Duplex Communication
```

---

# 🔁 Transaction Flow

The SPI transaction follows this sequence:

```text
                 +------+
                 | IDLE |
                 +--+---+
                    |
                 start = 1
                    |
                    v
            +---------------+
            | Load TX Data  |
            +-------+-------+
                    |
                    v
            +---------------+
            |    CS = 0     |
            +-------+-------+
                    |
                    v
            +---------------+
            | Generate SCLK |
            +-------+-------+
                    |
          +---------+---------+
          |                   |
          v                   v
     Rising Edge          Falling Edge
          |                   |
     Sample MISO          Change MOSI
          |                   |
          +---------+---------+
                    |
              8 Bits Complete?
                    |
                   Yes
                    |
                    v
            +---------------+
            |    CS = 1     |
            +-------+-------+
                    |
                    v
            +---------------+
            |    DONE = 1   |
            +-------+-------+
                    |
                    v
                 +------+
                 | IDLE |
                 +------+
```

# 🧩 Internal Architecture

The SPI Master consists of the following major components:

### 1. TX Shift Register

Stores the data that needs to be transmitted.

```text
tx_data → TX Shift Register → MOSI
```

The register shifts one bit at a time during the SPI transaction.

---

### 2. RX Shift Register

Receives serial data from MISO.

```text
MISO → RX Shift Register → rx_data
```

After 8 bits have been received, the complete byte is available in `rx_data`.

---

### 3. Clock Divider

The system clock is divided to generate the SPI clock.

```text
System Clock
     |
     v
Clock Divider
     |
     v
   SCLK
```

The clock divider is controlled through the parameter:

```verilog
parameter CLK_DIV = 2
```

---

### 4. Bit Counter

The bit counter tracks the number of transferred bits.

```text
0 → 1 → 2 → 3 → 4 → 5 → 6 → 7
```

After 8 bits have been transferred, the transaction is completed.

---

### 5. Control Logic

The control logic manages:

* Transaction start
* Chip select
* Clock generation
* Data shifting
* Bit counting
* Transaction completion

# 🧪 Verification Strategy

The design is verified using a **loopback testbench**.

In loopback mode:

```text
MOSI ───────────────► MISO
```

Therefore:

```text
TX Data = RX Data
```

For example:

```text
TX = 10100101

MOSI:
1 0 1 0 0 1 0 1

MISO:
1 0 1 0 0 1 0 1

RX = 10100101
```

# 📈 Waveform Verification

The testbench generates a VCD file:

```text
spi_master.vcd
```

Important signals to observe in GTKWave:

```text
clk
rst
start
cs
sclk
mosi
miso
busy
done
tx_data
rx_data
```

### Expected waveform behavior

```text
CS

__________|------------------------|__________


SCLK

__________|_|-|_|-|_|-|_|-|_|-|_|-|_|________


MOSI

          1  0  1  0  0  1  0  1


MISO

          1  0  1  0  0  1  0  1


BUSY

__________|------------------------|__________


DONE

___________________________________|‾|________
```

The key verification points are:

* `CS` goes LOW during the transaction.
* `SCLK` toggles for 8 clock cycles.
* `MOSI` transmits 8 bits.
* `MISO` receives 8 bits.
* `BUSY` remains HIGH during the transaction.
* `DONE` pulses HIGH after completion.
* `RX_DATA` matches `TX_DATA` in loopback mode.

# ⚠️ Current Limitations

The current implementation is intentionally kept simple for learning and RTL practice.

Current limitations include:

* 8-bit data width
* SPI Mode 0 only
* Single SPI Master
* No dedicated SPI Slave module
* Loopback-based verification
* No configurable CPOL/CPHA
* No FIFO interface
* No burst transaction support
* No error detection mechanism
